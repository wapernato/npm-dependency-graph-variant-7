# Сравнение порядка с npm — этап 4

Независимая проверка: Node.js 22.14.0 / npm 10.9.2, 9 ноября 2026.
Анализатор использует BFS и алгоритм Кана, npm вызывается только для сверки.

| Пакет | Порядок программы (слева направо) |
| --- | --- |
| is-odd@3.0.1 | is-number@6.0.0 -> is-odd@3.0.1 |
| is-even@1.0.0 | is-buffer@1.1.6 -> kind-of@3.2.2 -> is-number@3.0.0 -> is-odd@0.1.2 -> is-even@1.0.0 |
| ansi-styles@4.3.0 | color-name@1.1.4 -> color-convert@2.0.1 -> ansi-styles@4.3.0 |

Для всех трёх пакетов реальные узлы и связи `npm ls --all --json` совпали
с графом анализатора. Для каждого ребра проверено: зависимость расположена
раньше потребителя. Установка npm в отдельном временном проекте:

```sh
npm install is-even@1.0.0 --ignore-scripts --no-audit --no-fund --omit=optional --legacy-peer-deps --loglevel=silly
npm ls --all
```

Фактические строки `placeDep ROOT` в логе npm для is-even идут в порядке:
is-even@1.0.0, is-odd@0.1.2, is-number@3.0.0, kind-of@3.2.2, is-buffer@1.1.6.
Это план размещения от корня к зависимостям, обратный нашему логическому
порядку для этой цепочки. placeDep не означает окончание сетевой загрузки.
Сеть и кеш npm работают параллельно, поэтому последовательность операций
не обязана совпадать с топологической сортировкой. Наш критерий —
готовность зависимостей до потребителя. Peer/optional/dev, lockfile,
platform, engines и hoisting не входят в модель анализатора и могут
создавать дополнительные отличия на других пакетах.

При цикле корректного топологического порядка нет; выдаётся ошибка.
При срезе по глубине порядок относится только к видимым узлам.
