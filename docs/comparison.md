# Сравнение с npm (9 ноября 2026)

Проверено на Node.js 22.14.0, npm 10.9.2, Java 27 (компиляция --release 17),
D2 0.9.0. Программа получает данные самостоятельно по HTTPS. npm используется
только как независимый контроль в тесте сравнения, не вызывается анализатором.

## Узлы, рёбра и изображения

| Пакет | Узлы | Рёбра | Совпадение с npm ls --all --json |
| --- | --- | --- | --- |
| is-odd@3.0.1 | 2 | 1 | Полное |
| is-even@1.0.0 | 5 | 4 | Полное |
| ansi-styles@4.3.0 | 3 | 2 | Полное |

Для каждого пакета успешно создан SVG из D2 и проверен визуально. Графы
содержат те же версии и связи, что штатное текстовое дерево `npm ls --all`.
Различается представление: npm рисует дерево и может повторять узлы;
D2 показывает ориентированный граф. Общее поддерево в графе не дублируется.
Стрелка направлена от потребителя к зависимости.

Исходные D2, SVG, текст программы и JSON/деревья npm сохранены в `output/`,
исключённой из Git как артефакты. Воспроизведение: `./scripts/demo.sh`,
`./scripts/compare-npm.sh` (для сравнения дополнительно нужны Node.js/npm).
Тест установки использует отдельную временную папку и `--ignore-scripts
--no-audit --no-fund --omit=optional --legacy-peer-deps`.

## Порядок загрузки

Логический порядок программы (каждая зависимость раньше потребителя):

- is-number@6.0.0 -> is-odd@3.0.1
- is-buffer@1.1.6 -> kind-of@3.2.2 -> is-number@3.0.0 -> is-odd@0.1.2 -> is-even@1.0.0
- color-name@1.1.4 -> color-convert@2.0.1 -> ansi-styles@4.3.0

Проверено для каждого ребра реального npm-дерева: индекс зависимости в
порядке программы меньше индекса потребителя.

В реальном логе `npm install --loglevel=silly` для is-even строки placeDep:

```text
is-even@1.0.0
is-odd@0.1.2
is-number@3.0.0
kind-of@3.2.2
is-buffer@1.1.6
```

Это порядок построения плана размещения npm: от корня к найденным
зависимостям. Он обратен нашему логическому порядку для этой цепочки.
placeDep не означает завершение загрузки или исполнения модуля. npm
разрешает и скачивает пакеты с кешем и параллелизмом; универсального
последовательного порядка загрузки у него нет. Поэтому совпадение списка
операций npm с топологической сортировкой не ожидается. В нашем списке
проверяется именно ограничение «зависимость до потребителя».

Для произвольных проектов возможны отличия: npm учитывает lockfile,
peer/optional/dev dependencies, engines, platform и hoisting/deduplication.
Здесь анализируются runtime dependencies и выбирается максимальная
версия в диапазоне независимо для каждого ребра. Это визуализатор графа,
а не полная реализация установщика npm. При цикле линейный порядок
невозможен; программа сообщает ошибку, но граф, D2, SVG и ASCII доступны.

Источники: [npm ls](https://docs.npmjs.com/cli/v10/commands/npm-ls),
[npm install](https://docs.npmjs.com/cli/v10/commands/npm-install),
[D2 CLI](https://d2lang.com/tour/man).
