# Этап 4. Порядок загрузки — вариант 7

```sh
./run.sh --package A --test --repository examples/diamond.json --mode order
./run.sh --package A --test --repository examples/chain.json --mode order
./run.sh --package A --test --repository examples/cycle.json --mode order
./run.sh --package is-odd@3.0.1 --mode order
./scripts/test.sh
```

Java 17+, все параметры описаны в [этапе 1](docs/stage1/README.md).
Граф сначала получается BFS предыдущего этапа. `LoadOrder.of` выполняет
итеративный алгоритм Кана с направлением «зависимость раньше потребителя».
При равноправных вершинах используется лексикографический порядок.
Для ромба: D -> B -> C -> A. Для цепочки: D -> C -> B -> A.
При цикле выводится ошибка, перечисляются оставшиеся блокированные узлы;
программа не выдаёт частичный результат за корректный порядок.
При ограниченной глубине порядок относится только к срезу (stderr предупреждает).
Фильтр и тестовый режим продолжают действовать; сравнение с настоящим npm
зафиксировано в [отчёте](docs/order-comparison.md).

npm не предоставляет гарантированного последовательного порядка скачивания:
сетевые операции могут идти параллельно; установка также учитывает peer,
optional, платформу, deduplication и lifecycle-скрипты. Здесь порядок —
логический топологический, runtime dependencies, без запуска скриптов пакетов.
